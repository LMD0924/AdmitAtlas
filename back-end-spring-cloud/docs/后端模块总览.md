# 后端模块总览

后端工程位于 `back-end-spring-cloud/`，父 POM 在此目录下，11 个模块**全部平铺**（Reactor 共 12 个工程，含父 POM），不再按 `common/` `services/` 二次分组。

## 运行形态：模块化单体（P1）

| 角色 | 模块数 | 特征 |
|---|---|---|
| 普通 library jar | 10 | 无 `main`、无 `application.yml`、不应用 `spring-boot-maven-plugin` |
| 可执行应用 | 1（`launcher`） | 唯一 `AdmitAtlasApplication`、唯一配置、唯一可执行 jar、唯一端口 8080 |

`launcher` 的启动类位于 `com.admitatlas` 根包，一次组件扫描装配所有模块的 `@Controller` / `@Service` / `@Repository` / `@Configuration`。业务模块之间不直接互相依赖，统一由 `launcher` 聚合，共享 `common-core` 的 `AdmitAtlasRepository`（**全工程一个 DataSource / JdbcTemplate**）。

## 模块清单

| 目录 | artifactId | 职责 | P1 关键类 |
|---|---|---|---|
| `common-core/` | `admitatlas-common-core` | 统一响应 / 错误码 / 异常 / 模块探针；共享只读 Model、位次与选科算法、JSON 与 ID 工具、统一免责声明、**唯一数据访问门面** | `Result`、`ResultCode`、`BizException`、`GlobalExceptionHandler`、`ModuleProbe`、`Models`、`AdmitAtlasRepository`、`RankCalculator`、`SubjectRequirements`、`Json`、`Ids`、`Disclaimer` |
| `api/` | `admitatlas-api` | 模块间共享 DTO 契约；P3 拆分时补 Feign 接口 | `ScoreInputDTO`、`MatchRequestDTO`、`MatchResultDTO`、`PlanSaveRequestDTO` |
| `gateway/` | `admitatlas-gateway` | 统一 Web 入口配置（CORS / 后续拦截器）；拆分时升级为 Spring Cloud Gateway | `ApiGatewayConfig` |
| `auth-user/` | `admitatlas-auth-user` | 成绩档案落库、演示用户信息；P1 未接鉴权 | `StudentController` |
| `school/` | `admitatlas-school` | 院校 / 专业档案检索、详情、字典 | `SchoolController` |
| `score/` | `admitatlas-score` | 一分一段、批次线、投档线、分数→位次换算 | `ScoreController` |
| `policy-rule/` | `admitatlas-policy-rule` | 省 × 年志愿规则、选科组合与逐条资格校验 | `PolicyController` |
| `match-engine/` | `admitatlas-match-engine` | **核心**：规则驱动、位次召回、选科过滤、加权位次、冲稳保分档、推荐依据、任务留证 | `MatchController`、`MatchService`、`MatchStrategy` 及三种实现、`MatchStrategyFactory` |
| `plan-report/` | `admitatlas-plan-report` | 方案校验 / 保存 / 载入 / CSV 导出 | `PlanController`、`PlanService` |
| `data-collector/` | `admitatlas-data-collector` | 数据版本公示与系统概览；P2 起扩展为独立采集子系统 | `DataVersionController` |
| `launcher/` | `admitatlas-launcher` | **唯一启动应用**：聚合全部模块，暴露 8080；Flyway 迁移与全部配置都在这里 | `AdmitAtlasApplication`、`SystemController`、`application.yml`、`application-mysql.yml`、`db/migration/V1__schema.sql`、`V2__seed_demo.sql` |

每个业务模块仍实现 `ModuleProbe`，`GET /api/v1/system/modules` 会列出它们，用于验证单启动类是否完整扫描。

## 其他目录

| 目录 | 内容 |
|---|---|
| `sql/` | `V1__init.sql`：MySQL 分区优化**参考脚本**，不参与启动、不由 docker-compose 挂载 |
| `deploy/` | `docker-compose.yml`（MySQL / Redis / Nacos，P1 主链路不依赖）、`nacos/README.md` |
| `data/` | H2 文件库（首次启动自动生成，已在 `.gitignore` 中忽略） |
| `docs/` | 本文件（模块总览） |

项目级设计文档统一放在仓库根的 `docs/`。

## 依赖方向

```
launcher ──> 各业务模块 ──> api ──> common-core
                     └────> common-core (Models / Repository / 工具 / Disclaimer)
```

- 禁止反向依赖（`common-core` 不得依赖任何业务模块）。
- 业务模块之间不直接互相依赖；共享DTO 放 `api`，共享行模型 / 工具 / 数据访问放 `common-core`。P1 已消除 `match-engine → auth-user` 与 `plan-report → match-engine` 的反向引用。
- 新增模块：在后端根目录建平铺目录 → 父 POM 加 `<module>` 与版本仲裁 → 实现 `ModuleProbe` → `launcher` 加依赖。

## 启动与验证

```bash
cd back-end-spring-cloud
mvn -B clean package          # 12 个 Reactor 模块 + 36 个测试
java -jar launcher/target/admitatlas-launcher-0.1.0-SNAPSHOT.jar --server.port=8080

curl http://localhost:8080/actuator/health
curl http://localhost:8080/api/v1/system/modules
curl http://localhost:8080/api/v1/system/overview
curl -X POST -H "Content-Type: application/json" \
  -d '{"provinceCode":"42","examYear":2026,"category":"物理类","totalScore":612}' \
  http://localhost:8080/api/v1/scores/convert-rank   # rank=12900（演示数据）
```

数据库由 Flyway 自动迁移，无需手动执行 `sql/V1__init.sql`。详细步骤见 [`../../docs/开发指南.md`](../../docs/开发指南.md)，端点清单见 [`../../docs/接口说明.md`](../../docs/接口说明.md)。
