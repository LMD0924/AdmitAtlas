# 开发指南

> 适用阶段：**P1 单省试点 + 双身份体系**。默认零外部依赖即可跑通全链路（H2 文件库 + Flyway 自动迁移 + 演示数据 + 内置演示账号）。

## 运行形态

后端是**模块化单体**：`back-end-spring-cloud` 下 11 个模块全部平铺（Reactor 共 12 个工程，含父 POM），其中 10 个是普通 library jar（没有 `main`、没有自己的 `application.yml`），只有 `launcher` 是唯一可执行的 Spring Boot 应用。

```
launcher (唯一 AdmitAtlasApplication, 8080)
  ├── common-core   ├── api           ├── gateway
  ├── auth-user     ├── school        ├── score
  ├── policy-rule   ├── match-engine  ├── plan-report
  └── data-collector
```

所有 Controller 在同一个 Spring MVC 上下文里，前端只访问 `8080`；`gateway` 模块承载 CORS 等统一 Web 配置，不再启动反向代理网关。`launcher/AuthWebConfig.java` 挂载 `AuthInterceptor`（只拦 `/api/**`），`common-core/.../auth/` 提供 `PasswordHasher`、`JwtUtil`、`AuthContext` 与 `AuthUser`。Spring Cloud / Nacos 依赖保留在 BOM 与 launcher 中，但默认关闭。

全工程共用**一个 `DataSource` 与一个 `JdbcTemplate`**，数据访问集中在 `common-core` 的 `AdmitAtlasRepository`；业务模块通过构造器注入调用，不各自建连接池。

## 环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| JDK | 17+（已在 JDK 21 / 24 下验证） | 编译目标 `release 17` |
| Maven | 3.8+ | 父 POM 统一仲裁依赖版本 |
| Node.js | 20+（已在 22 下验证） | Vite 5 |
| 数据库 | **无**（默认 H2 文件库） | `back-end-spring-cloud/data/admitatlas.mv.db`，首次启动由 Flyway 自动建表并灌入演示数据 |
| MySQL | 8.0+（可选） | 切 `--spring.profiles.active=mysql` 时使用，连接信息走环境变量 |
| Docker | 可选 | `deploy/docker-compose.yml` 起 MySQL / Redis / Nacos，P1 主链路不依赖 |

P1 未接入 Redis、Elasticsearch、MinIO；这些是 P2/P3 的基础设施目标。

## 构建与测试

```bash
# 后端：全量编译 + 运行 70 个测试（只有 launcher 生成可执行 jar）
cd back-end-spring-cloud
mvn -B clean package

# 跳过测试快速打包
mvn -B -DskipTests clean package

# 只跑测试
mvn -B test

# 只编译某模块及其依赖（需先 install 父 POM 与依赖模块）
mvn -B -DskipTests -pl match-engine -am package

# 前端
cd ../front-end
npm install
npm run dev        # 开发服务器 http://localhost:5173
npm run build      # 产物 front-end/dist
npm run preview    # 预览构建产物
```

后端共 **72 个单元测试**（`common-core` 密码哈希 / JWT / 拦截器、`auth-user` 登录注册退出与**登录失败冻结状态机**、`match-engine` 匹配、`plan-report` 校验与导出等），`mvn -B clean package` 一次跑完。演示账号哈希由 `PasswordHasher` 生成，V5 迁移与前端一键填入口令同源，避免哈希漂移。`mvn -B test` 会从父 POM 开始按 Reactor 顺序执行，单独对某模块用 `-rf` 时需先 `mvn install` 安装依赖模块。

## 端口

| 端口 | 用途 | 说明 |
|---|---|---|
| 8080 | 后端统一入口 | 唯一进程，所有 `/api/**` 与健康检查都在这里 |

## 启动与验证

```bash
# 1. 启动唯一应用（自动执行 Flyway 迁移，无需先建库）
cd back-end-spring-cloud
java -jar launcher/target/admitatlas-launcher-0.1.0-SNAPSHOT.jar --server.port=8080

# 2. 验证（另一个终端）
curl http://localhost:8080/actuator/health                       # {"status":"UP"}
curl http://localhost:8080/api/v1/system/modules                 # 8 个业务模块
curl http://localhost:8080/api/v1/system/overview                # 阶段 / 数量 / 数据版本
curl http://localhost:8080/api/v1/match/strategies               # 三种考试模式

# 3. 位次换算（演示数据：612 分 → 12900 名）
curl -X POST -H "Content-Type: application/json" \
  -d '{"provinceCode":"42","examYear":2026,"category":"物理类","totalScore":612}' \
  http://localhost:8080/api/v1/scores/convert-rank

# 4. 登录取 token（内置演示账号；匹配 / 成绩 / 方案接口都需登录）
TOKEN=$(curl -s -X POST -H "Content-Type: application/json" \
  -d '{"username":"student","password":"Student@123456"}' \
  http://localhost:8080/api/v1/auth/login | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

# 5. 完整匹配（返回 25 条候选、冲稳保分档与免责声明）
curl -X POST -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"score":{"provinceCode":"42","examYear":2026,"examMode":"GROUP_3_1_2","category":"物理类","subjectCombo":["物理","化学","生物"],"totalScore":612,"subjectScores":{}}}' \
  http://localhost:8080/api/v1/match/analyze

# 6. 管理员后台（学生 token 访问会返回 403）
curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/v1/admin/overview
```

启动日志里应出现 `"1 - schema"` ~ `"5 - login lock"`：全新库为 `Successfully applied 5 migrations ... now at version v5`，从旧库升级则增量应用缺少的迁移。端点清单、权限矩阵与请求 / 响应示例见 [接口说明](接口说明.md)。

前端联调：先启动后端，再 `npm run dev`，浏览器打开 `http://localhost:5173`。首页「当前数据规模」显示 3 / 14 / 120 即表示前后端已连通（数字有滚动动画，滚动到卡片才触发）。

## 演示账号与鉴权

| 账号 | 密码 | 角色 |
|---|---|---|
| `student` | `Student@123456` | STUDENT |
| `admin` | `Admin@123456` | ADMIN |
| `demo` | `Demo@123456` | STUDENT（P1 演示数据归属 `id=1`） |

- 游客可访问首页、院校库与公开规则；成绩、匹配、方案需登录；`/api/v1/admin/**` 仅 ADMIN。
- 登录返回 HS256 JWT，后续请求带 `Authorization: Bearer <token>`；密钥由 `ADMITATLAS_AUTH_SECRET` 注入，默认 12 小时有效。
- 退出登录 / 停用账号 / 重置密码都会递增 `token_version`，旧 token 立即失效。
- 自助注册强制 STUDENT；管理端可创建 ADMIN。所有管理端写操作写入 `audit_log`。
- 连续输错 5 次会按账号冻结 30 分钟（`code = 423`），前 4 次响应带 `remainingAttempts`；登录页显示倒计时。管理员重置密码 / 启用账号可提前解锁。
- **生产部署必须删除内置演示账号并覆盖默认密钥**；仓库内的默认值仅供本地演示。

## 配置说明

- **唯一配置文件**：`back-end-spring-cloud/launcher/src/main/resources/application.yml`。要改端口、应用名、actuator 暴露项、匹配参数都改这一处。
- 默认数据源：`jdbc:h2:file:./data/admitatlas;MODE=MySQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1`，数据文件在 `back-end-spring-cloud/data/`，已加入 `.gitignore`。
- **数据库迁移由 Flyway 统一管理**：`launcher/src/main/resources/db/migration/` 下 `V1__schema.sql`（H2 / MySQL 通用 DDL）、`V2__seed_demo.sql`（演示数据）、`V3__auth_roles_audit.sql`（账号字段 / `audit_log` / `data_version_registry` / 内置账号）、`V4__school_profile_avatar.sql`（院校 Markdown 资料 + 头像列）、`V5__login_lock.sql`（`login_attempt` 表 + 演示账号哈希对齐）。**不要修改已应用的 V1~V5**：Flyway 校验 checksum，改动会导致 `Migration checksum mismatch` 启动失败；需要修数据时新增 V6。不要手动执行 `sql/V1__init.sql`，也不要让 docker-compose 挂载 initdb 脚本——那是 MySQL 分区优化参考，与 Flyway 重复建表会冲突。
- 演示数据：`admitatlas.demo-data: true`、`data-version: demo-2026-hb-v1`，所有录取数值均为合成值；切生产时设 `demo-data: false` 并注入已发布版本。
- 认证参数：`admitatlas.auth.secret`（`${ADMITATLAS_AUTH_SECRET:...}`）、`token-hours`（默认 12）。生产必须覆盖密钥。
- 匹配参数：`admitatlas.match.history-years`（默认 3）、`rank-window-low/high`（0.55 / 1.9）、`chong-boundary`（-0.10）、`bao-boundary`（0.15）、`max-candidates`（60）。
- MySQL profile：`application-mysql.yml`，连接串 / 账号 / 密码走 `ADMITATLAS_DB_URL` / `ADMITATLAS_DB_USER` / `ADMITATLAS_DB_PASSWORD`，数据版本走 `ADMITATLAS_DATA_VERSION`。
- `spring.cloud.nacos.discovery.enabled: false`、`config.enabled: false`。接入注册中心时改为 `true` 并启动 Nacos。
- 敏感配置一律走环境变量或配置中心，**禁止硬编码**；本地可新建 `application-local.yml`（已在 `.gitignore` 中忽略）。

## 从单体拆成微服务（P3）

1. 给目标模块补 `XxxApplication` 启动类与 `application.yml`（端口、应用名）。
2. 在该模块 `pom.xml` 中重新应用 `spring-boot-maven-plugin`，从 `launcher` 的依赖里移除它。
3. 把 `gateway` 模块升级为真正的 Spring Cloud Gateway（WebFlux），配置 `lb://admitatlas-xxx` 路由。
4. 模块间调用改为 `api` 模块中声明的 Feign 契约；共享 `AdmitAtlasRepository` 需按数据所有权拆分；业务代码与 `MatchStrategy` 实现无需改动。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| `mvn package` 报找不到 main class | 正常：只有 `launcher` 声明了 `spring-boot-maven-plugin`，其余模块是普通 jar。请从 `launcher/target/` 启动 |
| `clean package` 无法删除 `admitatlas-launcher-0.1.0-SNAPSHOT.jar` | Windows 下旧 `java.exe` 仍占用 jar；先停止运行中的 launcher 进程再重新打包 |
| 启动时出现 `H2 2.2.224 is newer than this version of Flyway` | 兼容性警告，迁移仍能正常应用；如需消除可显式锁定 Flyway / H2 版本 |
| `Migration checksum mismatch for migration version N` | 已应用的 V1~V5 文件内容被改动。**不要改历史迁移**，改回原内容或删除本地 H2 库文件（`./data/admitatlas.mv.db`）让 Flyway 全新重建；修数据应新增 V6 |
| `Database may be already in use` / `The file is locked` | 同一份 H2 文件库被两个进程打开（例如 IDEA 与命令行各跑一个）。停掉多余进程，或统一 Working directory |
| 改了迁移后 IDEA 里 admin 登录提示账号或密码错误 | 旧库仍用旧哈希。删除本地 H2 库重新迁移，或确认 V5 已应用；密码以登录页「一键填入」为准 |
| 受保护接口返回 `code = 401` | 未带 `Authorization: Bearer <token>`、token 过期，或账号被停用 / 重置密码 / 退出后 `token_version` 已变化；重新登录即可 |
| 新增写接口未受保护 | 受保护路径是显式登记的，需同步在 `AuthInterceptor.PROTECTED_PATHS` / `ADMIN_PATHS` 与 [接口说明](接口说明.md) 中登记 |
| 新增模块没被扫描到 | 确认包名在 `com.admitatlas` 下，且 `launcher/pom.xml` 已声明该模块依赖；用 `/api/v1/system/modules` 复核 |
| 启动时反复连 Nacos 报错 | 确认 `spring.cloud.nacos.discovery.enabled: false`；或启动 Nacos 后改为 `true` |
| 访问不存在的路径返回 500 | 全局兜底异常处理器只捕获 `RuntimeException`，404 由 Spring 默认处理；若自定义了 advice 不要覆盖 checked `ServletException` |
| 前端请求 404 | 确认 Vite `proxy` 指向 8080，且后端已启动 |
| 首页统计数字一直是 0 | 数字用 `v-count` 滚动入场动画，需滚动到「当前数据规模」卡片才触发；异步数据到达后指令会重新计数。若始终为 0 先查 `/api/v1/system/overview` |
| 中文乱码 | 导出 CSV 已带 UTF-8 BOM；Maven 与前端文件统一 UTF-8，MySQL 使用 `utf8mb4` |
| `npm install` 返回 403 | 部分环境默认镜像为 `http://registry.npmmirror.com`（HTTP 可能被拦截），改用 `npm install --registry=https://registry.npmjs.org` |
| 端口被环境变量覆盖 | 沙箱可能注入 `SERVER_PORT`，启动需显式覆盖：`java -jar ... --server.port=8080`；普通环境直接用 yml 即可 |
| `mvn -rf :模块名 test` 报找不到同项目依赖 | `-rf` 从中间模块恢复时前面的 jar 未安装；改用完整 `mvn -B test`，或先 `mvn -B -DskipTests install` |

## 代码规范

- 后端包名必须合法（模块名带连字符时，Java 包名去掉连字符，如 `policy-rule` → `com.admitatlas.policyrule`）。
- 所有 Controller 返回 `Result<T>`，业务异常抛 `BizException`；前端 Axios 统一解包 `data`。业务服务取当前用户一律用 `AuthContext.userId()`，禁止再写死 `DEMO_USER_ID`。
- 数据访问统一走 `AdmitAtlasRepository`，候选召回的位次窗口必须下推到 SQL（命中 `idx_query`），不要在应用层全量过滤。
- 跨年比较只用 `min_rank`；合规文案统一引用 `common-core/Disclaimer.java`，禁止出现「录取率 / 保证录取」。
- 新增业务模块时：在 `back-end-spring-cloud/` 下建平铺目录 → 父 POM 加 `<module>` 与版本仲裁 → 实现 `ModuleProbe` → `launcher` 加依赖。
- 新增省份规则只改数据（`rule_policy`），不改代码；新增策略实现 `MatchStrategy` 接口并注册为 Spring Bean。
- 新增手写体中文文案时，`public/fonts/MaShanZheng.woff2` 是子集化字体，需重新生成子集，否则新字会回退到系统字体。
